## Changes and capability candidates

- All then-current integration entities loaded. Core robot, map, room, settings, schedule,
  history and diagnostic surfaces remained available after the OTA.
- The robot reported no active Hermes error codes during inspection.
- `coverage_time` is unknown because v168.11 currently returns the known
  16-byte tombstone/default form. This is expected, not a regression.
- With explicit owner approval, the two-byte diagnostic-upload value was
  inspected locally and not retained. It is protobuf field 2 with a direct
  boolean `true` value. The current decoder accepts only the older
  length-delimited field-2 form, so installed integration 0.1.1 correctly fails
  closed to `unknown`. The current tree now accepts both forms with synthetic
  regression fixtures. This was decoder drift, not an endpoint failure.
- The integration detail page reports 0.1.1. The HACS update entity reported an
  older installed value, so the integration page is used as authority here.
- No new endpoint, payload shape, or capability was established by this check.

## 0.2.0 release verification (2026-07-21)

- Integration 0.2.0 installed live via HACS on the same robot and firmware.
- The automatic typed-registry snapshot covered all 40 endpoints with
  **28 populated, 12 empty, 0 failed**; the 8 names that rejected the generic
  stream path in the manual sweep are now read through their evidence-backed
  property shapes. Compatibility status recorded as `baseline`.
- The diagnostic-upload binary sensor resolved from `unknown` to the
  robot-reported boolean, confirming the released dual-form decoder.
- Robot-side stream resets during bounded collection reads were observed
  live (`h2` StreamClosedError) and are handled as normal transport noise
  in 0.2.0; they previously failed whole poll cycles on 0.1.x.

## 0.3 protocol research (2026-07-27)

- A bounded active-run subscription produced 444 trajectory messages: 421 route
  updates and 23 mission-scoped clear markers. Every message matched the active
  floor-plan mission; the largest route contained 166 finite 2D points.
- The public client accepts only the verified envelope, limits payload and point
  counts, rejects non-finite or extreme coordinates, and requires the active
  mission ID. Home Assistant exposure remains pending privacy and performance review.
- Acknowledged collection snapshots validated all 20 retained session images,
  one monthly recap, and both 781-page semantic layers. The semantic layers have
  identical page keys and one mission identity; their bounded decoder preserves
  all 32 × 32 native cell grids while rejecting malformed metadata and dimensions.
- The native flythrough snapshot contains 1,606 finite camera poses and matches
  that same map mission. Its bounded client decoder rejects stale missions,
  malformed vectors, unsafe coordinates, excessive poses, and oversized payloads.
- These newly decoded history and map surfaces remain client-only. They are not
  exposed in entity state, Recorder, diagnostics, media endpoints, or the browser.
