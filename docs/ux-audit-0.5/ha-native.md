# Home Assistant-native surfaces: UX audit (0.5 candidate, base c00f878)

Structure and behavior of config/options flows, entities, actions, Repairs, blueprints, LLM tools and events. Wording-only problems in these strings are scored in `copy.md`; IDs of withdrawn rows are retired, not reused. Rows follow the severity rules and codes in `docs/ux-audit-0.5.md`. Every claim was checked against this tree; width is n/a for HA-native surfaces. Scratch proofs (outside the repo, all passing): update entity (ENT-01), manual step (FLOW-08), setup abort (FLOW-01), both Reconfigure paths (REP-01).

Findings: 52 (P0 2, P1 12, P2 32, P3 6). By surface: config flow 13, options flow 6, entities 10, actions 8, Repairs 6, blueprints 6, LLM tools 3.

## Owner decisions already taken
- Entities are renamed and duplicates are removed.
- Entity unique_ids stay stable, so entity IDs do not change.
- Identity-changed recovery requires a fresh Bluetooth re-pair; certificate pinning is never relaxed.
- Developer actions get an "Advanced:" name prefix.
- Every Direction below conforms to these decisions.
