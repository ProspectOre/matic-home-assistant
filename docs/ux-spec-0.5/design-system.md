# Map Studio 0.5 design system: `ms-*` refinement spec

Refines `frontend/map-studio-v4/tokens.ts`, `controls.ts`, `shell-styles.ts` and the component style blocks. Paths are relative to `frontend/map-studio-v4/` unless prefixed; measured numbers come from `tests/browser/ux-audit-tools/*.mjs` (named per claim) on synthetic gallery fixtures, and contrast values are computed with the WCAG formula from HA's default palette (`ha_theme_axe.mjs:8-21`). `plan.md`, `room-schedule.md`, `home-rooms.md`, `shell.md` and `map-surfaces.md` cite the token names, sizes and detent numbers below as final.
## 1. Scope
- Covers tokens, control primitives, type, spacing and nesting, contrast, forced colors, motion, RTL, focus rules, and sheet/inspector geometry for every Map Studio surface. Per-state behaviour and copy belong to `shell.md`; the plan and room layouts belong to `plan.md` and `home-rooms.md`.
- Audit IDs: MS-RESP-01–09, MS-TOUCH-01–04, MS-AXE-01–03, MS-KEY-01–03, MS-DS-01–09 (`responsive-a11y.md`); the design-system parts of MS-HOME-09/10/11, MS-ROOMS-10, MS-PLAN-10/11/13/14/20/23, MS-DRAW-06 and MS-STATUS-03/08/09.
- Owner decisions touched: refine `ms-*` (no `ha-*`/`mwc` rewrite, no iOS skin); HA theme tokens stay the colour source; Stop stays reachable without confirmation, in its invariant place, at every width; the shell invariants stay.
## 2. User goal
A household administrator opens Matic Map on a phone, tablet or desktop in their own Home Assistant theme and expects one consistent app that feels native to it. Within two seconds they must see what is tappable, what is selected, which button is the main action and where Stop is, in light, dark, high-contrast, RTL and 400% zoom.
## 3. Hierarchy
- **390 (sheet)**, top to bottom, placed by `shell.md` and `map-surfaces.md`: app bar (`--ms-bar`, 56 px: menu, title, robot picker, Full map toggle, Map options ⋮) → canvas with `.ms-surface--floating` clusters (rail: floor, Fit, "?"; camera steps; dock) → sheet: grip row (handle, status line, one detent toggle) → Draw tool rows (Draw only) → `h2` → notice slot → scrolling body → pinned action bar. As at 1024, the `h2` and notice slot are pinned above the scrolling body (shell.md:14, 43; map-surfaces.md:13).
- **1024 (inspector, `--ms-inspector`, 360 px)**: app bar → canvas | inspector: status strip (Stop at its inline end, shell.ts:1317-1320) → `h2` → notice slot → scrolling body → pinned action bar.
- **The one primary action** is `.ms-btn--primary.ms-btn--lg.ms-btn--block` in the pinned action bar (44 px tall inside the compact grip row, §7); paused Resume at ≥1024 px is the one exception, placed in the status strip beside Stop by `shell.md` §3, which leaves the bar empty. No other control in that view uses `--primary` (`C-OneAction`).
- **Stop** uses the danger fill (`.ms-btn--primary.ms-btn--danger`) at every width while the robot works, and the outline `.ms-btn--danger` only beside Resume when paused (MS-STATUS-06). `shell.md` owns its placement. The system guarantees that Stop never takes `--sm`, never scrolls away, and always sits in a pinned bar or the strip.
- Layering is unchanged: canvas rail 4 (map-canvas.ts:101) < sheet 7 (shell-styles.ts:261) < precision controls 8 (precision-controls.ts:41) < precision popover and Full map HUD 9 (shell-styles.ts:116, 203) < app bar 12 (51) < menu 18 (87) < dialog 30 (231) < skip link 40 (33).

- **Dark mapping.** Each tint is one `light-dark(<12% mix>, <20% mix>)` colour pair, never a switched percentage (MS-HOME-11). Only the shell host sets `color-scheme` (`light dark`, following the OS as the tokens.ts:81 query does today), so every shadow root inherits it; Decision 3 sets it from HA instead. Where `light-dark()` is unsupported (before Chrome 123, Firefox 120 and Safari 17.5 per MDN, not verified against Home Assistant's supported browsers or the companion-app WebViews), both fallback sets sit only inside `@supports not (color: light-dark(#000, #fff))`: the 12% mixes, then the 20% mixes in a nested `prefers-color-scheme: dark` query; the unconditional dark block (tokens.ts:81-99) is untouched. Text on a tint is `--ms-text` (≥8.6:1) or the row second-line mix (controls.ts:109, ≥6.6:1 on the accent tint), never `--ms-text-quiet` (4.42:1 on the dark warning tint).
- **Token rules.** No `--ms-*` token assigns an HA variable, and no HA variable is overridden unconditionally. `:host` holds only surface-independent values (tokens.ts:7-16); tints mix against `--ms-surface-card`, never `--ms-local`, so they qualify.

## 5. Rules
- **Contrast.** Text on its surface or fill must reach ≥4.5:1, and focus, selection and control boundaries ≥3:1 (WCAG 1.4.3, 1.4.11), measured with HA's default palette (`ha_theme_axe.mjs`), never with the component fallbacks. Text never uses a raw tone colour: notices, due lines and warning or success text lines use `--ms-text` with a tone glyph (there is no warning or success text token); routine due work takes the due glyph (`mdiCalendarCheck`, a new path) and the warning glyph (`mdiAlert`) marks only a blocker; the outline danger button its 82% mix (5.68:1 light, 4.76:1 dark), and any other danger text `--ms-danger-text`.
- **Contrast resolver (adopted only through Decision 1).** The shell runs `theme-probe.ts` on connect and on the triggers map-canvas.ts:419-430 already watches; it resolves colours to sRGB (theme-probe.ts:66-91) and uses the WCAG ratio `(L1 + 0.05) / (L2 + 0.05)`. Fill pair (F = `--primary-color` or `--error-color`, T = `--text-primary-color`): a ratio ≥4.5 keeps both; otherwise the first F_k = `color-mix(in srgb, F k%, black)` (white when T is darker than F), for k = 95, 90 … 50%, that reaches ≥4.5 wins; if none does, F stays and the label becomes whichever of #000 or #fff contrasts more. Indicator (A = `--primary-color`): kept when ≥3 against both `--ms-surface-card` and `--ms-surface-sunken`, otherwise the same search (toward black on light surfaces, white on dark). Danger text (`--error-color` on `--ms-surface-card`): kept at ≥4.5, otherwise the same search.
  - HA defaults: Run 3.26 → `#007b9f` (80%, 4.85:1); Stop 4.29 → `#d04134` (95%, 4.68:1); indicator `#008bb3` (90%, 3.12:1 on `#e5e5e5`), unchanged in dark (5.23 and 4.53:1); danger text 4.29 → `#d04134` (95%, 4.68:1) light and 3.97 → `#df574b` (90% toward white, 4.55:1) dark. The resolver writes only the six `--ms-resolved-*` properties on the shell host, never an HA variable; forced colors bypass it.
- **Control sizing.** Every interactive hit box (element plus its label, as `touch.mjs` measures) is ≥ `--ms-control` (44×44) at every pointer. The only exception is `.ms-btn--sm`: 36 px on a fine pointer, 44 under `(any-pointer: coarse)`, which covers touch laptops and tablets at ≥1024 px. Sizes: icon buttons 44×44 with a 20 px glyph; text buttons 44 px tall with `--ms-space-3` inline padding; action-bar buttons `--lg` 52 px (44 px in the compact grip row); selects, inputs, steppers and ranges 44 px; checkbox and radio rows and disclosure summaries are full-row 44 px targets. Row leads and status icons stay 36 px and are never targets. Draw tools stay 48.4 px on the regular sheet (`responsive.mjs`) and are 44 px on the compact sheet.
- **Type scale.** There are two body steps: `--ms-t-md` 14 px (body, row titles, buttons, fields, notices) and `--ms-t-xs` 12 px (second lines, hints, captions, field labels, action summary). There is one section-heading style (`.ms-section-heading`); it shares 14/700 with row titles on purpose and differs by colour and the 24 px space above. Titles: `--ms-t-lg` 16/700 for the app title, dialog title and narrow sheet status (the 14 px overrides at shell-styles.ts:313 and 359 go); `--ms-t-xl` 20/700 with `--ms-track-tight` for the workflow `h2`. Weight is the secondary axis: within a size, 700 marks a title, heading or button, 500 a field label or value, and 400 everything else. No uppercase or positive tracking anywhere. This replaces 12/13/14/20 (`ds.mjs`) plus map-canvas's 0.7, 0.74 and 0.82 rem and weights 650 and 750.
- **Nesting.** At most one bordered container (`.ms-surface`, `.ms-row`, `.ms-notice`) sits between the panel and any control; a field's or stepper's own border does not count (`ds.mjs`: 6 controls at depth 2 today, target 0). Inside it, groups are separated by space and a section heading, never by a border or a sunken fill; selected rows tint, and their contents never re-border.
- **Spacing rhythm.** 4 px (`-1`) from label to control and from icon to text; 8 px (`-2`) between list rows, between buttons, and from a field to its hint; 12 px (`-3`) for row padding and between fields in a group; 16 px (`-4`) for panel and sheet padding and between groups; 24 px (`-5`) above a section heading.
- **Literals.** Every colour, font size, weight, radius, gap and duration in a style block is a token; map geometry (map-canvas.ts:203-204, 216, 220) may stay literal. map-canvas.ts: 148, 169, 172, 212 → `--ms-t-xs`; 234 → `--ms-t-md`; 166 → `--ms-t-lg`; 154, 213 → `--ms-w-bold`; 171 → `--ms-w-medium`; 161 → `var(--ms-w-bold) var(--ms-t-xs) var(--ms-font)`; `44px` (101, 106, 110, 119, 161) → `--ms-control`; `52px` (109, 113, 117) → `calc(var(--ms-control) + var(--ms-space-2))`; paddings, gaps and radii (147, 151, 153, 169-176, 229) → space and radius tokens; the focus and selection colours at 96, 159 (zone stroke), 162 (zone-point ring) and 165 (zone-point focus), plus shell-styles.ts:373 (scrim focus) → `--ms-indicator`; the invalid stroke at 160 → `--ms-danger`; the zone feedback text at 176 (4.29:1 light, 3.97:1 dark today) → `--ms-danger-text`; the zone-point number at 161 (accent on card, 3.26:1 light; 5.23:1 dark passes) → `--ms-text`, and 163-164 → the accent fill pair; 162 → `--ms-shadow-1`; 179-180 → `--ms-surface-card`/`--ms-text`.
- **Forced colors.** Filled buttons (primary and danger fill) set `forced-color-adjust: none; color: HighlightText; background: Highlight; border-color: Highlight` (`forced.mjs` before/after: the blank label is fixed). Disabled keeps GrayText label and border (controls.ts:189). The focus ring (`--ms-indicator` → Highlight) is never removed; selected rows and pressed buttons keep their Highlight fill with HighlightText (controls.ts:188), and the switch keeps Highlight (157-161).
- **Forced colors on canvas and tones.** The canvas palette comes from system colours (theme-probe.ts:106-120), the selected-room stroke becomes 2 px (1.5 px today, renderer-controller.ts:1397), and the canvases keep `forced-color-adjust: none` (map-canvas.ts:260). Tones become CanvasText (tokens.ts:123-125), so the words carry the tone. `.ms-notice` and `.ms-stepper` get a CanvasText border in the controls.ts forced-colors block (186-190), because they render outside the shell root. The canvas palette's accent reads `--ms-indicator` instead of `--ms-accent` (theme-probe.ts:22), so the selected-room stroke (renderer-controller.ts:1404) follows Decision 1.
- **Motion.** Durations come only from `--ms-fast` and `--ms-base`, which are zeroed under reduced motion (tokens.ts:100-107). No literal durations, and no `@keyframes` without a reduced-motion override. The sheet transition is `none` under reduced motion (shell-styles.ts:381-383) and inertia is off (gesture-controller.ts:619). Today 0 animations run under reduced motion (`forced.mjs`); the chevron and toast motion follow the same tokens.
- **RTL and zoom.** Use logical properties only (the symmetric handle `translateX(-50%)` at shell-styles.ts:307 may stay). Directional icons follow §4, and roving arrows already flip (roving-focus.ts:87-88). No fixed heights on text containers. At 400% zoom the compact layout applies (§7).
- **Focus on entry and exit.** Entering a workflow focuses its `h2[tabindex=-1]` (shell.ts:549, 554-562) with no visible ring (shell-styles.ts:255). Every entry records its launcher, not only entries that need draft confirmation (shell.ts:597-605); exit restores it if it is still connected and visible, otherwise the destination heading, never `body` (K2d, K3d). Dialogs focus the safe choice, trap focus and restore `data-dialog-launcher`, falling back to the workflow heading (MS-KEY-03).
- **Menus and Escape.** Menus contain `.ms-row--menu` rows only, in labelled groups: action rows (`menuitem`), radio rows (`menuitemradio` with `aria-checked`) and switch rows (`menuitemcheckbox` drawn with `.ms-switch`); no segment and no native select, so Scene detail becomes four radio rows. Map options' "Map display" group (Photo and Room colors radio rows, then a Room names switch row) is `home-rooms.md`'s. Opening a menu focuses its first row (replacing shell.ts:469-472); Escape closes it and restores the ⋮ launcher; the native-select Escape guard stays (gesture-controller.ts:76, #108). The full Escape order is `shell.md`'s.
- **Roving focus.** Only toolbars rove (draw tools, draw-tools.ts:34; camera steps, map-canvas.ts:290-293, 598): one tab stop, RTL-aware arrows, Home and End, calling `preventDefault()` per roving-focus.ts:3-6. Pressed-button groups, lists and stepper parts are ordinary tab stops; the stepper field steps with native Up/Down.

## 10. Decisions needed
1. **Contrast-resolved colours (MS-AXE-03).** This changes the HA → `ms-*` colour mapping that Phase D freezes, for fills, the focus and selection indicator (rings, borders, the canvas selection) and tone text. *Recommended:* keep each HA colour when it reaches its ratio on its surface (4.5:1 text and labels, 3:1 indicator); otherwise step it toward black on light surfaces or white on dark in 5% steps (§5; with HA's defaults: Run `#007b9f`, Stop `#d04134`, indicator `#008bb3` on light, danger text `#d04134` / `#df574b`). *Alternatives:* a black label on HA's fills (6.45:1 and 4.89:1), with the indicator and text still resolved; or HA's colours unchanged (Run 3.26:1, Stop 4.29:1, danger text 4.29 / 3.97:1, indicator 2.59:1 on sunken), which fails WCAG 1.4.3 and 1.4.11. Until this is decided, every new resolved-colour token (the six in §4) equals HA's value; the `--ms-tint-*` mixes are not resolved colours and are excluded.
2. **The frozen 768-landscape row.** This spec implements the row as written: a 320 px inspector with a 448 px (58%) canvas; the ≥60% target belongs to the 1440 row only. Amend the row only if the owner prefers the sheet there. *Recommended:* do not amend.
3. **Dark-mode source.** *Recommended:* the shell sets its host's `color-scheme` from `hass.themes.darkMode` (the OS when absent), so tints and native controls follow HA's own dark setting, and map-canvas repaints on that change as well as on its OS query (map-canvas.ts:426); no HA variable changes. *Alternative:* keep following the OS (today), which mis-shades whenever HA's theme and the OS disagree.
- **Owner decisions (2026-10-11):** all recommendations accepted. D1 contrast-resolved colours in 5% steps wherever HA's value misses its ratio (the six §4 tokens take the resolved values); D2 the 768-landscape row is not amended; D3 dark mode follows `hass.themes.darkMode`.
