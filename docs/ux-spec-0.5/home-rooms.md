# Home and rooms: 0.5 UX spec

Source paths are relative to `frontend/map-studio-v4/` unless prefixed; audit IDs come from `docs/ux-audit-0.5/`. Siblings are referenced, not restated: `plan.md` (Run/Edit views, picker, the due lines `v4_due_*`), `shell.md` (status strip and all its copy, notice rule, shape and keys, toast, host-state copy, dialogs, Stop placement, detent behaviour), `design-system.md` (tokens, sizing, contrast, type scale, menus, detent numbers, header widths, focus-restore rule).

## 1. Scope
- **Surfaces:** home (`workflow: "none"`) in every host and activity state; the one-time room clean (`workflow: "rooms"`); the narrow-only Display group; the multi-robot header.
- **Audit IDs:** MS-HOME-01, 02, 03, 04, 06, 07, 09, 10, 11; MS-ROOMS-01 to 08, 10, 11; MS-STATUS-02 (home side), 04, 05 (home side); MS-HOST-02, 03, 07 (home panel); MS-RESP-01 (home/rooms content), 05, 07; MS-TOUCH-01, 04 (Clear chip); MS-KEY-01 (home launchers); MS-AXE-01; MS-PLAN-10 (home/rooms rows).
- **Owner decisions touched:** the Apple-level bar; refine `ms-*`; the shared room schedule is the default, and one-time cleans follow it; Stop keeps its invariant place with no confirmation; the shell invariants (one primary action, room/list parity, fail-closed selectors).

## 2. User goal
A household administrator opens Matic Map to start a clean (some rooms now, a saved plan, or a drawn area) or to stop the one running. In two seconds they must see what the robot is doing, whether they can start something now, and the one thing to tap.

## 3. Hierarchy
- **Home at 390** (sheet at `half`, shell.ts:189), top to bottom: (1) the grip, with handle and status line (`shell.md`); (2) the `h2` (by state, §4); (3) the notice slot, directly under the `h2` as in every workflow (`shell.md` §4 rule 2); (4) one description line, only when the cards are unavailable; (5) three task cards: **Clean rooms** (featured), the **plan card**, and **Clean custom area**; (6) the **Maps** heading with the Map history and Map diagnostics rows, nothing else (today the shelf holds the custom area and history only, shell.ts:1156-1167); (7) the pinned action bar, showing Stop or Resume while the robot works (`shell.md` places Stop). When idle the action bar container is absent, not empty: today `choose-cleaning` renders no button (shell.ts:948) inside a padded `.action-bar` (shell.ts:983). The Display group (shell.ts:1168-1197) leaves home (§5).
- **Home at 1024:** the status strip, with Stop as its action while the robot works (shell.ts:1317-1320, :1547-1551), then items 2–6, then the action bar when it has a button. The canvas shows the map with no room highlight.
- **Rooms at 390** (`half`, shell.ts:190), top to bottom: (1) the grip, with back and, at peek, "{count} selected · names" (shell.ts:1263-1272); (2) the `h2` "Choose rooms" with back to "All tasks"; (3) the notice slot; (4) the description; (5) the list header: "Rooms to clean", "{count} selected" and Clear (at least one selected), plus the limit line when full; (6) the **Cleaning settings** row; (7) the check lines, stacked, each only when needed: the due lines (`v4_due_*`, `plan.md`, with the due glyph), then `v4_room_parts` when `missionBoundaries` is non-empty, then the failed or blocked line (R4). The "Effective cleaning preview" section and its heading go (workflow-panel.ts:290-317); (8) room rows in catalog order; (9) the pinned action bar: one summary line and **Clean {count} rooms**, replaced in place by Stop while the robot works.
- **Room row** (an `.ms-row` with a `.ms-check` label, `design-system.md` §4), inline start to end: the `<label>` spans the row up to the trailing button and holds the checkbox, the name (`<bdi>`) and, on selected rows only, a second line: the effective setting (`v4_room_setting_*`, which already shows the due work that will run), with no due chip, plus a third line for any other `cadenceReasons` entry. The label is the 44 px target, so a tap on the name toggles selection exactly as the checkbox does. On selected rows, a sibling outside the label at the inline end is a 44×44 **Settings** button: chevron-down glyph (`iconChevronDown`, chevron-up when open), named "Settings for {room}" (`v4_room_settings_named`, defined here). It expands the row's two selects below the label. Unselected rows show the checkbox and name only. `plan.md` Edit uses the same `.ms-row` with the checkbox as its own 44 px target and the name inside a disclosure button, so there a tap on the name expands the row instead of selecting it.
- **Rooms at 1024:** the strip (Stop while the robot works), the same panel, the action bar. Selected rooms are highlighted on the canvas, with the chip "{count} selected · Clear" (map-canvas.ts:686-694).

## 5. Interaction
- **Cards.** Each card is an `ms-row` button. A disabled card is `aria-disabled` with `aria-describedby` pointing to the one description line, and tapping it does nothing. Clean rooms opens Rooms, and Custom area opens Draw, as today. The plan card (D1) opens the `plan.md` Run view (`workflow: "plan"`, `planView: "run"`) for `plans.selectedPlan` (backend-contracts.ts:258, set at plans.py:2560-2561) when that plan is on this floor; otherwise it opens the picker, or the picker's empty state when there are no plans. Back from Run returns where the user came from: home card → home, picker → picker.
- **Display (narrow).** Map options (⋮) gains a first "Map display" group in every workflow, rows only (`design-system.md` §5 Menus): Photo and Room colors as radio rows (top view only, the rule at map-canvas.ts:554), then a Room names switch row. Help moves to the rail "?" (`shell.md`). Wide keeps the rail controls.
- **Parity.** The list checkbox, a tap anywhere on a row's label, and a map tap (under 7 px, gesture-controller.ts:358-365) dispatch one `toggle-room`. The row, map highlight, header count, grip line, chip and summary update in one render. The list keeps catalog order (`plans.value.rooms`) and never reorders, and every label uses the catalog `name`. The map draws the selection fill and stroke whenever Rooms has a selection; today they show only with Room names on or with Room colors in top view (renderer-controller.ts:1396). The selection never shows on home. A map room with no catalog entry cannot be selected; today it falls back to the scene id (renderer-controller.ts:1603-1606). Neither map nor list shows numbers (`C-OrderBadges`); run order appears only in the summary.
- **Settings.** The Cleaning settings row is one disclosure (`aria-expanded`) holding Cleaning mode and Vacuum coverage for the whole clean. Its value is the row's setting string, or "Different per room". A change rewrites every selected room and becomes the default for rooms selected later; today new rooms start at vacuum/standard (state.ts:444-448).
- **Due work and per-room settings.** Only when a selected room has due schedule work does the settings row also hold the "Include scheduled work that's due" switch. On means `useRoomSchedule: true` (default, state.ts:137), and `override_room_schedule` is sent unchanged (effects.ts:2561). Each selected row's Settings button opens its two selects inline, with one disclosure open at a time. When due work changes a room's effective setting away from its selects, the row's second line shows the effective setting (what will run), and the due lines above the rows say which work is due; the disclosure adds nothing. The "Ready" tag (workflow-panel.ts:247) is removed.
- **Clean.** The primary runs the existing preflight (`#cleanRoomsFromPreview`, effects.ts:2511), then Starting. With no rooms it stays `v4_action_clean_rooms`, disabled with its reason; "Start cleaning" never appears on Rooms. The request always sends `return_to_base: true` (effects.ts:2562), so the summary always says the robot returns to the dock. It lists rooms in preview order and never reads `planDraft.returnToBase` (shell.ts:979).
- **Selection gate.** Rows, Clear and map taps share `canSelectRooms` = `canEditCoordinates` (state.ts:722-730) and not `hasStoppableWork` (state.ts:823-830). When the map is not ready, rows become `aria-disabled` as map taps stop working, and the primary's reason says why. While work runs they are `aria-disabled` with `v4_rooms_busy` as the shared description, so they stay focusable (`shell.md` §5). A tap on a blocked map toggles nothing and re-announces the reason already on screen once through the polite region (shell.ts:1576); no toast or notice. The workflow never changes by itself, because workflow and activity stay orthogonal (docs/architecture-0.5.md:76). Back leads to H4. The selection is kept until Clear.
- **Keyboard.** Enter on a card focuses the workflow `h2` (shell.ts:549, :554). In Rooms, Escape closes an open disclosure first, then exits. Exit restores focus to the launching card (MS-KEY-01; the rule is in `design-system.md`). Space toggles a row; Enter opens a disclosure.
- **Dialogs and reversibility.** No dialogs: home and rooms have no destructive action, and Stop is never confirmed. Selection, settings and Back are all reversible.
- **Feedback at 390 and 1024.** An accepted start shows Starting, then Cleaning, in the grip or strip, and the primary becomes Stop in place. A failure shows in the slot under the heading: at 390 it is visible at `half` and `full`, and at `peek` the `shell.md` toast carries it. A rejection also toasts at both widths.

## 8. Accessibility
- **Targets.** Cards stay 54–69 px (MS-DS-09). A room row's `.ms-check` label spans the row up to the Settings button, with `min-block-size` set to `--ms-control` (today `--ms-control-sm`, workflow-panel.ts:60). Settings buttons are 44×44. Clear, in the header and on the chip (today 50×36, map-canvas.ts:691), gets a 44 px floor under a coarse pointer. The robot select is 44 px tall.
- **Contrast.** Text on the featured tint, the selected-row tint and filled buttons follows `design-system.md`'s rule: keep HA's pair when it reaches 4.5:1, otherwise darken the fill or use a black label. The selected-row border and the map selection stroke use `--ms-indicator`, ≥3:1 against the card and sunken surfaces (`design-system.md` §5). Reason lines stay ≥4.5:1. Tints keep equal strength in dark mode (MS-HOME-11).
- **Forced colors.** Selected rows get the Highlight fill with HighlightText, and the native checkbox (`controls.ts:188`, `design-system.md` §5). Disabled cards use GrayText. The featured card uses a CanvasText border instead of a tint.
- **Reduced motion.** Disclosures and card demotion have no transition.
- **Screen readers.** `.quick-actions` (shell.ts:1115) gains `role="group"` with its name; the room list already has it (workflow-panel.ts:234). The "Shared room schedule status" div (workflow-panel.ts:267) goes (MS-AXE-01). Disclosures expose `aria-expanded` and `aria-controls`. Map toggles announce through the polite region (shell.ts:1576). Notices follow `shell.md`: its two regions announce them, so the slot carries no live role.
- **RTL.** Chevrons mirror per `shell.md`, layout uses logical properties only, and room lists use `Intl.ListFormat(locale)`.
- **Multi-robot header (MS-HOME-09, MS-RESP-07).** Title and robot-select widths and bar order at 320 and ≥360: `design-system.md` (its MS-RESP-07 row). This spec adds only that the select's accessible name stays "Choose robot" and that, with more than one robot, the strip and grip name the robot (`shell.md`).

## 9. Backend needs
