## 2. User goal
A household administrator opening Matic Map wants to know what the robot is doing, whether anything needs them, and how to stop it. Within two seconds they read the robot's state and its consequence on one line, find Stop where it was last time, and see the one next action without the map being covered.

## 3. Hierarchy
- **390 (sheet), top→bottom:** app bar (menu, title, robot select per `home-rooms.md`, Full map toggle, Map options ⋮) → canvas (rail; state chip at top centre over a map, centred card on an empty canvas; toast on the sheet's top edge) → sheet: grip (handle, status line, one detent toggle) → h2 → notice slot → scrolling body → action bar (inside the grip row on compact sheets, `design-system.md` §7).
- **1024 (360 px inspector), top→bottom:** status strip (glyph, title, detail; Stop at its inline end; reasons directly under it) → h2 → notice slot → scrolling body → action bar (workflow primary). The h2 and slot are pinned above the scrolling body (`design-system.md` §3). Canvas: rail, chip, dock, toast at bottom centre above the dock.
- **One primary** from `selectPrimaryAction`; while the robot works it is Stop (danger fill), except in history and on a saved floor, where "Show live map" (:850) or the read-only reason (:859) stays primary and Stop is the secondary (`state.ts:1083-1086`). With more than one robot the strip title and grip line show the status, then the robot name, as two text runs joined by the strip's " · " separator, state first so truncation keeps it; no composed string, since placeholders hold data only (`copy-style-0.5.md:96`).
- **Stop, invariant place:** wide = trailing slot of the status strip; narrow = the action bar at every detent; Full map = the HUD. Paused, Resume (`resume` :897), or "Check robot status" after a rejected Resume (`recheck-status` :874), sits beside Stop in that place: wide, [Resume][Stop] share the strip's trailing slot on one row, leaving the wide action bar empty, and the strip detail truncates with an ellipsis first, never a second strip row; narrow, [Resume][Stop] at equal width (today ~750 px apart on wide, `shell.ts:1317-1330`). Resume stays the single `selectPrimaryAction` result, so there is still one contextual primary. Stop is never behind a dialog, detent, scroll or menu and never asks for confirmation.

### Notice rule (shared; no spec adds another notice surface)
0. **Ownership:** this spec owns the shape, both surfaces and the global notices in §6 (connection, map change, saved map, motion, status refresh, start guard, saving); workflow notice texts stay in their own specs (`plan.md` `v4_notice_plan_*`, `home-rooms.md` `v4_notice_room_preview_*`, `map-surfaces.md` `v4_notice_area_*`).
1. **Shape (UX0):** `interface WorkspaceNotice { readonly tone: "info" | "success" | "warning" | "error"; readonly key: string; readonly fallback: string; readonly placeholders?: Readonly<Record<string, string | number>> }` replaces `{tone, text}` (`contracts.ts:195-198`). A notice is one sentence with at most one action besides dismiss, and Close is not an action (`copy-style-0.5.md:91`). No notice in this spec carries an action (the next step is the sheet's recovery verb), so the UX0 shape has no action field. Views render `translate(localize, key, fallback, placeholders)`; effects never build text (the prefix at `effects.ts:1727` becomes `v4_notice_saved_map` with `{date}`). Notices are compared by key, never by text. Effects stop emitting `RECONNECT_NOTICE` and `LIVE_MAP_RECHECK_NOTICE` (`effects.ts:104,106`), so their comparisons go (`effects.ts:550` entirely); `effects.ts:1514` keeps one key comparison that clears `v4_notice_saved_map` when the live map settles.
2. **Slot, every workflow:** the shell renders the notice once, directly under the h2 and above the description (`shell.ts:1256-1258`), in `none`, `rooms`, `plans`, `plan`, `draw`, `areaReview`, `history` and `support`, pinned with the h2 so it never scrolls away; on wide it sits just below the strip that holds Stop. The end-of-form calls (`workflow-panel.ts:285,768,831`) go.
3. **Toast:** one shell region, newest wins. Shown for every `success` and `error` (C-Feedback: inline error + toast) and for `info`/`warning` only when the slot is off-screen (sheet at peek, Full map). Anchors: wide = bottom centre of the canvas above the dock; narrow = the sheet's top edge; Full map = above the HUD. Hides after 4 s (success), 6 s (info, warning) or 10 s (error), paused while hovered or focused; Close is 44 px. Hiding a toast never clears the slot.
4. **Tones:** each tone has a glyph (info, check, alert, alert-circle) and a tint (`design-system.md`; today `workflow-panel.ts:49-51`); colour is never the only cue.
5. **Lifetime:** the slot's Close dispatches `set-notice` null (`contracts.ts:300`); effects replace or clear notices; success clears on workflow change (`state.ts:296`); Escape never dismisses a notice.
6. **Announcements:** each notice is announced once, through two static regions the shell owns and nothing else writes to: the existing polite region (`shell.ts:1576`) for info, success and warning, and a sibling `role="alert"` region for error, so a rejected Stop interrupts. Static regions are used because changing a live region's role at runtime is announced unreliably. Slot, toast and canvas chip carry no live role (drop `role` at `workflow-panel.ts:170` and `map-canvas.ts:747`). The polite region also announces each status title change once (not battery ticks) and detent changes; the canvas region (`map-canvas.ts:752`) keeps only the map description.

## 5. Interaction
- **Stop:** one tap, no dialog; dispatches `stop_intelligent_cleaning` (`effects.ts:2384-2386`). Press → `settling` → row 15 at once; acceptance → the backend fence keeps row 15; rejection → row 15's feedback. Disabled reason, first match: unreachable (`host.connected` or `robotConnected` false) → `v4_reason_stop_unreachable`; not an administrator → `v4_reason_stop_admin`; `settling` → `v4_reason_stop`; a save or delete in flight (`pending`) → `v4_reason_stop_busy` (today always "already stopping", `state.ts:845`). Shown at every width.
- **Recovery verbs** (sheet body, secondary style, one per state): "Try again" runs the existing `recheck-status` effect (`effects.ts:2371-2382`); "Open map diagnostics" opens `support`; the No robot link is `home-rooms.md`'s.
- **Locating escalation (D1 default):** the 20 s timer belongs to the Locating episode, not the view: the shell (not the sheet or HUD) starts it when the strip enters row 8 (`coherence` `booting` or `verifying`; `degraded` is row 8's "Map limited" case and has no timer). It keeps its elapsed time across Full map entry and exit, so a user who exits as the HUD says finds "Try again" at once. It resets only when the episode ends: Locating ends, a higher row takes the strip (Stop pressed → row 15, disconnect → row 1), or the entry or floor changes. Locating that persists after Stopping ends is a new episode and starts at zero. At 20 s the sheet adds `v4_locating_slow` and "Try again"; the Full-map HUD only swaps its detail to `v4_locating_slow_full` and keeps Stop and Exit, with no new button. "Try again" keeps its label and is disabled while the refresh runs, and the strip detail reads `v4_locating_rechecking` meanwhile; when it settles the episode's timer restarts at zero, and a failed catalog refresh adds `v4_notice_recheck_failed` (warning). Nothing is sent to the robot, and action admission never changes. Copy support info (MS-HOST-04 Direction) is left out to keep one verb; diagnostics stays in Maps.
- **Save in `discardDraft`:** offered only when the current primary is `save-plan` (plan Edit) or `save-area` (area review) and enabled; Draw drafts (primary `review-area` :965) get none. Save dispatches that action (`effects.ts:2474-2479`). In flight (`pending`): every button keeps its label and is disabled (`copy-style-0.5.md:83`; `plan.md:36` agrees), the dialog body adds `v4_notice_saving` "Saving…" as its status line, and Escape is ignored. Success: the same draft turns non-dirty with its success notice (`effects.ts:2333-2337`; areas already close the dialog, `effects.ts:2253`), so the dialog closes, the pending navigation continues to its target view without discarding (`shell.ts:607-620`), and the toast shows. Rejection (error notice; `command` returns to idle, §6): the dialog closes and the user stays in plan Edit (`save-plan`) or area review (`save-area`) with the draft kept, error in slot and toast. Keep editing: the dialog closes and the user stays. Disconnect or entry change mid-save (the effect returns silently, `effects.ts:2599`): handled as a rejection, with the strip at Reconnecting. The launcher recorded through `needsDraftConfirmation` (`shell.ts:597-605`) gets focus back whenever the user stays.
- **Focus and Escape:** entering a workflow focuses its h2 (`shell.ts:548-562`); every entry records its launcher and every exit restores it (MS-KEY-01; today only for dirty drafts, `shell.ts:597-605`); if the launcher is gone (deleted plan row, closed menu, removed control), focus goes to the destination's h2. Moves to a deeper view (plans → plan, draw → areaReview) are entries; Back and Done are exits. Map options focuses its first button, not the select (`shell.ts:469-472`), keeping the native-select Escape guard (`gesture-controller.ts:76`). Escape order: Map options → help → dialog (discard = Keep editing) → precision → Full map → workflow (`shell.ts:897-915`, `state.ts:557-571`); plan views per `plan.md`.
- **Sheet:** peek/half/full on regular sheets; peek/full on compact sheets (height < 480), with the action bar in the grip row (`design-system.md` §7). Handle drag, flick, tap-to-cycle and body swipe stay (`shell.ts:726-826`); the two chevrons become one toggle (expand, or collapse at full) and the unavailable direction is hidden. Starting detents replace `DEFAULT_DETENT` (`shell.ts:188-197`) and re-apply on a `planView` change. Regular: none, rooms, plans, plan Run, areaReview, history = half; plan Edit = full; draw = peek; support = full under 600 px wide, half from 600 (`design-system.md` §7 follows). Compact: rooms, draw, areaReview, history = peek; none, plans, plan, support = full. Heights: `design-system.md`.
- **Workflow gating (UX2):** the `.workflow-fields` fieldset (`workflow-panel.ts:950`), which disables every workflow control whenever `command` is neither idle nor failed, is removed. Each control is gated by its own `aria-disabled` + reason under the unchanged selectors (`canStartMotion`, `canEditCoordinates`, `hasStoppableWork`, `command`). Where a spec names no per-control reason for a busy or pending state, the workflow's one description line is the `aria-describedby` of all its rows (the home H4 pattern): Rooms rows while the robot works use `v4_rooms_busy` (`home-rooms.md`), and Edit rows while a save is pending use `v4_reason_plan_saving` (`plan.md`).
- **Diagnostics:** rows show plain sentence-case values; the copied text keeps raw values and the privacy allowlist is unchanged. Copy summary is never disabled: today it renders outside the fieldset (`workflow-panel.ts:934,950`), and it takes no gate once the fieldset goes.
